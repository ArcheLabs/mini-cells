# Continual Learning Core: From Write Addressability to Dependency-Scoped Transactional Growth

**Stage question:** What is the smallest controlled mechanism that combines regression safety with sufficient plasticity?

Core Validation 001/001B investigated knowledge subsumption and residual memorization. Validation 002 found `WRITE_ADDRESSABILITY_NOT_SUPPORTED`; 002B found `SPARSE_WRITE_ASSEMBLY_NOT_SUPPORTED`; oracle 002C found `ORACLE_SPARSE_ASSEMBLY_NOT_SUPPORTED`. These negative results removed precise semantic write addresses as a prerequisite.

Validation 003 changed the address from knowledge content to execution dependency. It recorded zero structural escape and zero false-safe events under frozen routing/shared state, but the official result remained `DEPENDENCY_SCOPED_TRANSACTIONAL_LEARNING_NOT_SUPPORTED`: safety was available while plasticity was insufficient.

Validation 004 added rollback-triggered, context-scoped growth. It passed all seeds (`80411`, `80412`, `80413`) with `GROWTH_RESTORED_PLASTICITY_SUPPORTED`. Growth therefore has a concrete role: create new degrees of freedom when dependency constraints block safe learning.

This is controlled synthetic evidence, not natural-language continual learning. See the [final report](../../reports/clm-core-mechanism-0.4.md), [validation protocols](../../validations/), and [canonical artifacts](../../../artifacts/experiments/).
