Import `notebook.ipynb` into the existing private `bingjiangli/minicells` Kaggle Notebook. Enable GPU, Internet, and existing `KAGGLE_API_TOKEN` / `GITHUB_TOKEN` Secrets, then Save & Run All. The notebook now calls **`run.py --pilot-only`**: only C1, batch 4, TBPTT 64, K=4, exactly 50 Trainer updates / 12,800 tokens. The first two successful updates are the numerical diagnostic and count toward the same 50 updates. Initial GradScaler scale is 1024; up to three consecutive FP16 gradient overflows are allowed. Each overflow skips clipping and the optimizer, applies scaler backoff, restores state/data/RNG and leaves scheduler/token/update counters unchanged. The same failed update is replayed in FP32 without updating weights; a finite FP32 result identifies the mixed-precision path, while a non-finite FP32 result stops the pilot for model/TBPTT diagnosis. Repeated retries reuse that FP32 diagnostic. Successful updates must also leave all parameters finite. After update 25, a newly constructed model/optimizer/scheduler/scaler resumes the saved checkpoint and continues to update 50. There is no duplicated GPU equivalence run, throughput benchmark, profiler, other model, validation, ablation, Inspector, or Bootstrap in this mode. It returns after publishing the pilot report and never automatically starts the 250K-token development run.

It contains environment and effective protocol configuration, 50 update metrics (loss, gradient/state norms), measured training tokens/s, peak allocated VRAM, restore status and the estimated C1 cost of 250K tokens. The estimate excludes data preparation and full validation and is not a runtime guarantee. The implementation has five small modules: `model.py` owns all differentiable transitions, `runtime.py` owns inference snapshots, `trainer.py` owns document-aware TBPTT and checkpointing, `data.py` owns Native TinyStories adaptation, and `diagnostics.py` / `storage.py` provide inspection and existing Kaggle transport integration. Native RMSNorm, SwiGLU, fixed dataset revision and ByteLevel BPE utilities are reused. BPE reconstruction uses the historical deterministic Native recipe; its actual hash is recorded rather than assumed identical to an unavailable historical asset. The development data manifest documents possible historical tokenizer exposure. No confirmation corpus is reused or opened.

C0 retains the same projection parameters as C1 but applies them only to its own cell. F0 has the same 2,048-number persistent state and low-rank dense recurrence; actual parameter and compute disparities must accompany comparisons. L0 retains only a four-token embedding FIFO and computes its state temporarily. Readout has no direct embedding bypass. State survives TBPTT boundaries; only document boundaries reset individual lanes.
