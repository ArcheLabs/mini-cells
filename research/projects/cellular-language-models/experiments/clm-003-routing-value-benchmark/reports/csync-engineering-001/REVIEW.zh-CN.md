# C-sync 工程实现与可行性结论

结论：**NO_GO**。实现及短程 CPU 路径已验证；没有证据证明当前匹配策略在代表性正式状态上可行。不得据此启动正式训练。

## 实现边界

历史 `screening.py`、`interpolation_audit.py`、`SCREENING_MANIFEST.json` 和旧 Notebook 保持不变。新 `implementation/csync.py` 提供 `accepted_event()`（从 A 更新前后状态导出同一 probe 的几何量）、`synchronize()`（C 自有模型上的受限随机搜索）、`feasibility()`（统计接受/匹配/失败）。A 的方向、梯度、标签和质量分数均不进入随机方向生成接口。

C 接入位置为原 Engine 主更新后的 pre-checkpoint failure_hook，须将事件嵌入曲线及同一恢复 Checkpoint。只允许完成对应步的 C Cell 更新后同步；重复事件文件立即阻断，恢复编排尚未开放为科学运行入口。A 拒绝时 C 不变；最多 K=8 个方向，每个方向 21 个固定尺度；按方向及尺度顺序接受首个合法匹配，绝不基于损失排序。三项几何指标均须匹配，绝对容差/相对容差及未匹配率上限见新 manifest。这些是冻结的工程候选规则，尚未获科学 GO。

probe 只接受输入、角色和内容哈希，禁止标签字段；身份校验不能代替其来源独立性核验，目前正式 probe 身份为空，运行会阻断。KL 沿用 old||new 的原始路由分布，旧状态聚合和完整路径独立闭环比较；参数差报告原始 L2 及每参数 RMS，保持合法 GraphConnection 结构。

## 实测与证据限制

针对性测试涵盖随机流复现及不扰动全局 RNG、标签/身份拒绝、三指标匹配、同步步校验、A 拒绝、UNMATCHABLE、候选上限、重复执行阻断、日志及成本。短程 native fixture 执行 A/C 各 2 步，输入序列一致，A 产生拒绝事件；C 未更新。这不是 500 步科学实验，也未恢复真实父权重。另一个强制不可能目标的失败路径完成 2×3 次测量，全部未通过合法性门槛；不能用它估计真实未匹配率。成功提交路径仅用明确标记的 mock sentinel 测试，不计入原生可行性证明。

`EVENT.json`、`REJECTED.json`、`UNMATCHABLE.json` 为日志样例。`FIXTURE_COST.json` 保留 A/C 训练及候选算力账本；事件成本包含搜索墙钟、CPU 随机采样时间、方向数、几何测量次数和失败次数。无 GPU 使用。正式工程预算最多 168 次候选测量/接受事件，最多 5040 次/三 Seed 的 30 个接受事件；应另计 A 优化与主训练成本，不宣称端到端成本相等。

## 未闭合项

1. 固定独立 routing-probe 输入及来源身份。
2. 旧筛查 Confirmation 已使用；新独立 Confirmation 未固定。
3. 当前主要指标容差下，真实工程状态匹配可行性及失败率未知。不得放宽容差制造 PASS。
4. 三 Seed 只作筛查；主要比较 A−C-sync，B 为辅助描述。不得将几何匹配成功视为事件质量收益证据，也不得把 A 接受时点上的条件比较推广为所有时点策略效应。

在上述条件满足、独立审阅及人工明确 GO 之前，不添加正式 GPU 启动入口。无需重跑旧 Phase 0 或 Cell-only 实验。
