# MiniCells 下一阶段实验方案：CLM 路由学习价值与模型性能基准

**版本：** v1.0  
**阶段：** CLM 路由学习价值验证与端到端基准测试  
**研究对象：** Cellular Language Model（CLM）  
**主要对照：** 固定随机 Connection、随机重连、标准 MoE、Dense 全激活模型

---

## 1. 实验目标

### 1.1 最终研究目标

CLM 的长期目标是：

1. 使用 Connection 承担类似 MoE Router 的路由功能。
2. 通过更小的路由参数量表达有效的路由策略，在较低的路由开销下达到与主流模型相近的任务质量。

当前阶段不要求证明 CLM 已经优于 MoE，而是检验其核心设计是否具有实际价值，并测量它与现有架构之间的性能差距。

### 1.2 本阶段必须回答的问题

**问题 A：Connection 是否学到了有价值的路由知识？**

学习后的 Connection 是否在独立测试数据上优于固定随机 Connection 和随机重连，而不只是产生参数变化或路由变化？

**问题 B：Cells 是否能够在当前联合训练机制下有效学习？**

在 Connection 学习与路由变化的情况下，整体模型是否能够继续改善任务质量？是否存在路由扰动导致的明显学习退化？

**问题 C：CLM 是否具有有竞争力的参数效率？**

在可比的模型容量、激活计算量和训练预算下，CLM 与标准 MoE、Dense 模型的质量和实际运行成本分别如何？

### 1.3 本阶段不要求证明的命题

以下事项不作为本阶段的前置条件：

- Cell 参数距离必须随训练单调增加。
- 每次 Connection 更新都必须扩大 Cell 分化。
- CLM 必须在所有任务上优于 MoE。
- CLM 必须在相同总参数量和相同激活计算量这两个不同条件下同时取得最优结果。
- 必须通过四格交叉评估才能确认整个架构具有可行性。

Cell 的功能专门化、路由稳定性和长期持续学习能力仍然需要记录和研究，但不应取代本阶段的主要性能目标。

## 2. 既有实验与证据边界

本阶段不得将不同算法的历史结果直接合并。

### 2.1 R3d

R3d 比较了固定原始 Connection、训练后冻结的 Connection，以及持续更新 Connection 的方案。

其结果表明，在 R3d 的特定算法和训练预算下，持续更新 Connection 没有优于只训练 Cells 的方案。

这不构成对 R3i 算法的直接否定。

### 2.2 R3i

R3i 实际执行了多次 Connection 更新和局部 Cell 适应，观察到部分更新改变了实际路由并产生可测量的局部 Cell 效应。

但其预注册的最终质量假设没有得到支持。局部适应现象不能直接证明联合训练已经产生可重复的整体质量收益。

### 2.3 CLM-002-FAST-002-R1

正式 Stage B 在五个 Seed 上执行了 500 步训练。H 路由下的平均 Development NLL 为：

| 实验组 | 平均 NLL |
|---|---:|
| B00：不更新 Cells 或 Connection | 5.48254 |
| B10：只更新 Cells | 5.45783 |
| B01：只更新 Connection | 5.48480 |
| B11：联合更新 | 5.46333 |

B10 相比 B00 在五个 Seed 上均改善了 NLL，说明现有架构下的 Cell 学习已有概念验证证据。

但 B00 不是随机路由对照，因此该实验不能直接证明学习后的 Connection 优于随机路由。联合训练的预注册协同假设也未得到支持。

参考结果：

- [CLM-002-FAST-002-R1 发布报告](https://github.com/ArcheLabs/mini-cells/tree/results/fast002-r1-b44a8869e349a67966cd3f989850b34a-6276e5432c58/research/projects/cellular-language-models/experiments/clm-002-fast-002-r1-stateful-calibration/reports/published/b44a8869e349a67966cd3f989850b34a)
- [R3i 科学结果](https://github.com/ArcheLabs/mini-cells/blob/main/research/projects/cellular-language-models/experiments/clm-001-qfirst-integrated/r3i/reports/published/4ef0eb15e8b3564748d917f19b003d6b5da2e816c6729721296974f28723f973/SCIENTIFIC-FINDINGS.md)

## 3. 核心实验组

本阶段设置五个主要实验组。

### A 组：Learned CLM

**目的：** 测量当前 CLM 联合训练机制的实际效果。

- Connection 根据训练信号进行学习和更新。
- Cells 正常训练。
- Connection 更新算法、更新频率、准入规则及训练预算全部预先固定。
- 不允许根据确认集结果临时修改算法。

这是实验组，也是后续与 MoE、Dense 比较的 CLM 主方案。

### B 组：Frozen Random Connection

**目的：** 测量学习 Connection 是否优于固定的随机路由策略。

- 从预先规定的合法 Connection 初始化分布中生成随机 Connection。
- Connection 在整个训练过程中不更新。
- Cells 正常训练。
- 保持模型拓扑约束、合法性要求及每次执行的计算规则与 A 组一致。

这里的“随机 Connection”并不意味着每个 Token 都必须独立随机选择路径。

如果 Connection 本身能够根据输入产生路由，那么冻结随机 Connection 仍然可以根据输入计算路径，只是其路由策略没有经过本实验中的学习更新。

A、B 两组应当使用相同的 Cell 初始参数和相同的训练数据。

为避免初始状态混淆，应从预先指定的共同父 Checkpoint 出发，在实验开始时生成合法的随机 Connection，并将其作为 A 组的初始 Connection；B 组保留同一个初始 Connection，不进行学习。

这样，A 与 B 的主要区别就是 Connection 是否通过训练获得更新。

### C 组：Random Rewiring

**目的：** 区分学习到的路由知识与单纯动态改变连接所产生的效果。

- 初始状态与 A、B 两组保持一致。
- Cells 正常训练。
- 每当 A 组在预注册的检查点实际提交一次 Connection 更新，C 组就在对应检查点执行一次随机重连。
- 如果 A 组没有提交更新，C 组也不进行对应的重连。
- 随机重连不得使用确认集标签或确认集质量来选择候选。

随机重连必须满足与 A 组相同的合法拓扑约束，包括允许的连接数量、扇入/扇出、路径长度和每次执行的计算约束。

如果架构允许通过 Connection 参数计算输入条件路由，C 组应当重新生成合法的随机 Connection 参数或拓扑，并在更新后继续使用该 Connection 的输入条件路由机制，而不是强行改成另一种路由架构。

应当记录每次重连造成的实际路径变化量。若无法精确匹配 A 组的变化幅度，必须明确报告差异，不得声称已经完全排除了扰动幅度的影响。

### D 组：标准 MoE

**目的：** 比较 CLM 与主流可学习路由机制的质量和计算效率。

- 使用标准 MoE 路由器和专家结构。
- 使用相同的任务、数据划分和评估协议。
- 尽可能匹配 CLM 的总模型参数量、每 Token 激活计算量和训练 Token 数。
- 如果无法同时匹配，分别开展总参数量匹配和激活计算量匹配的比较。

必须记录 MoE 路由器的参数量、专家参数量、激活参数量、路由开销和实际推理成本。

### E 组：Dense 全激活模型

**目的：** 提供不依赖稀疏路由的质量—计算参考点。

- 使用 Dense 模型。
- 所有模型参数均参与每次前向计算。
- 使用相同任务和数据。
- 尽可能匹配 CLM 的总模型参数量，并记录更高的实际激活计算量。

Dense 组不是唯一的胜负标准。其主要作用是显示全参数激活能够获得的质量，以及为此支付的计算成本。

## 4. 实验公平性与共同配置

所有组别必须在正式实验前确定共同配置。

### 4.1 共同初始状态

- 记录父 Checkpoint 的精确版本和哈希。
- A、B、C 使用相同的 Cell 初始参数。
- A、B、C 使用同一个预先生成的合法随机 Connection 作为共同初始连接。
- 记录每组的优化器状态、初始化随机种子及数据游标。
- D、E 使用各自架构的标准初始化，但必须记录初始化方法和参数量。

如果现有可用 Checkpoint 已经包含与特定 Connection 长期协同训练的 Cells，应明确其历史。不能将这种 Checkpoint 当作未经路由适应的初始模型。

### 4.2 数据与训练预算

所有组别应使用相同的数据集版本、训练集、验证集和独立确认集。

至少需要记录：

- 训练 Token 数；
- 优化器更新步数；
- 数据顺序；
- 训练 Seed；
- 每 Token 的实际计算量；
- Connection 更新或随机重连次数；
- 总训练时间和计算成本。

相同的训练 Token 数不代表相同的总计算成本。Connection 候选评估、随机重连、MoE 路由以及未采用的候选分支所产生的成本，都必须记录。

### 4.3 训练、选择和确认数据

预先划分：

1. **Train：** 用于参数更新。
2. **Development：** 用于训练过程监控和预先规定的检查。
3. **Calibration：** 如需进行候选选择，只能使用此集合。
4. **Confirmation：** 只用于最终确认，不能用于更新准入、模型选择或阈值调整。

已有的 Development 和 Calibration 数据曾被反复使用，不能默认它们仍然是独立确认集。

如果无法建立独立 Confirmation 集，本轮结果必须标记为探索性实验，不得声称完成了独立确认。

## 5. 主要指标

### 5.1 主要指标一：Connection 学习价值

比较 A、B、C 三组在独立确认集上的端到端任务质量。

以 NLL 为例，定义：

\[
\Delta_{A-B}=\mathrm{NLL}_{A}-\mathrm{NLL}_{B}
\]

\[
\Delta_{A-C}=\mathrm{NLL}_{A}-\mathrm{NLL}_{C}
\]

负值表示 A 组更好。

主要假设为：

- A 优于 B：学习 Connection 比冻结随机 Connection 更有效。
- A 优于 C：学习 Connection 比同更新时点的随机重连更有效。

要支持“Connection 学到了优于随机的路由知识”，应当要求这两项比较均具有可重复的正向证据，并达到预先规定的实际意义阈值。

只观察到 A 组路由变化更多，或者 A 组参数更新更多，不构成成功证据。

### 5.2 主要指标二：端到端模型质量

使用独立确认集上的 NLL 或预先规定的任务指标。

对语言模型，应至少报告：

- Token 平均 NLL；
- Perplexity；
- 适用任务的准确率或其他任务质量指标。

主要模型质量比较为：

- CLM 与标准 MoE；
- CLM 与 Dense。

“相近效果”必须转化为预先规定的非劣界限，而不是实验完成后根据结果定义。

设非劣界限为 \(m_{\mathrm{NLL}}\)，则只有在预先规定的统计判定下，CLM 相对 MoE 的质量差异没有超过该界限，才能称为达到预定的质量非劣标准。

该界限应根据任务、基线变异和实际应用要求在确认实验之前确定。

### 5.3 主要指标三：路由参数效率

必须分别报告：

- Connection 参数量；
- MoE Router 参数量；
- 总模型参数量；
- 每 Token 实际激活参数量；
- 每 Token 实际计算量；
- Connection 或 Router 的推理开销。

CLM 的目标不只是拥有更少的路由参数，而是以更少的路由参数达到有竞争力的端到端质量。

因此，必须将路由参数量与模型质量联合报告，不能只比较 Router 的参数规模。

### 5.4 主要指标四：实际运行成本

在相同硬件和可比运行配置下，报告：

- 推理吞吐量；
- 中位数和 P95 推理延迟；
- 峰值内存；
- 实际每 Token 计算量；
- 总训练时间和总训练成本；
- 路由计算所占的时间或计算比例。

稀疏执行不自动等于更低延迟。实际收益必须通过运行数据确认。

## 6. 次要诊断指标

以下指标用于解释机制，不作为必须满足单调增长的成功条件。

### 6.1 路由质量

记录：

- 不同输入类别的路由分布；
- 路由熵；
- 路径变化频率；
- Cell 调用频率；
- 路由负载分布；
- 路由在不同训练阶段的稳定性。

如果任务具有已知类别或已知计算需求，可以测量路由选择与任务需求的对应程度。

### 6.2 Cell 功能分化

不能仅以参数距离判断专业化。

应当尽可能测量：

- 各 Cell 在不同输入类别上的输出差异；
- 各 Cell 对最终任务损失的边际贡献；
- 移除某个 Cell 后的性能变化；
- 路由选择与 Cell 功能贡献之间的对应关系；
- 功能分化是否在后续训练中保持。

参数距离可以作为辅助指标，但不应被要求单调增加。

### 6.3 Cell 学习能力

记录各组 Cell 参数变化、训练损失和独立验证质量变化。

本阶段的目的不是重新证明 Cell-only 学习，而是确认在可训练 Connection 和随机路由控制下，Cells 的学习是否能够支持端到端模型质量。

## 7. 统计分析与预注册

### 7.1 独立 Seed

每组应使用多个独立训练 Seed。优先采用配对 Seed，使不同组尽可能共享相同的初始 Cell 状态、数据顺序和外生随机流。

训练 Seed 是衡量训练随机性的重要单位。

不能用同一个 Seed 下大量样本的 Bootstrap 结果替代独立训练重复。

Seed 数量应在实验开始前根据既有 Seed 间变异、最小有意义的效应和资源预算确定。若样本量不足以支持确认性判断，应将实验标记为探索性。

### 7.2 主要比较的多重检验

预先规定主要比较的顺序：

1. A 对 B：学习 Connection 是否优于冻结随机 Connection。
2. A 对 C：学习 Connection 是否优于随机重连。
3. A 对 D：CLM 与 MoE 的质量和效率比较。
4. A 对 E：CLM 与 Dense 的质量和效率比较。

预先规定置信区间、显著性水平、实际意义阈值及多重比较校正方法。

不得在观察结果后改变主要指标、排除不利 Seed，或者只报告表现最好的检查点。

### 7.3 最终确认

所有主要质量比较必须在独立 Confirmation 集上执行。

如果 Confirmation 结果被用于选择新的模型或训练配置，则该集合不再是独立确认集。后续确认必须使用新的留出数据。

## 8. 实验执行顺序

### 阶段 0：冻结实验规格

- 固定当前 CLM Connection 算法和版本。
- 固定共同父 Checkpoint。
- 固定随机 Connection 的生成分布与合法性约束。
- 固定 A 组的更新检查点和准入规则。
- 固定 C 组与 A 组的重连时点匹配规则。
- 固定模型配置、数据划分和统计判定标准。

在所有主要配置确定之前，不启动正式确认性训练。

### 阶段 1：A/B/C 路由学习价值实验

先运行三个 CLM 组别：

- A：学习 Connection 与 Cells 联合训练；
- B：固定随机 Connection，只训练 Cells；
- C：在 A 的实际 Connection 提交时点进行随机重连，同时训练 Cells。

这一阶段直接回答 Connection 是否学到了优于随机路由的知识。

若 A 没有优于 B 和 C，应当先分析路由学习机制，而不是直接将结果解释为 CLM 不可行。

### 阶段 2：Dense 与 MoE 基准

在共同任务和数据上运行 D、E 组。

至少分别开展：

1. 相同或可比的总参数量比较；
2. 相同或可比的每 Token 激活计算量比较。

如果资源只允许先完成一种匹配条件，应优先保证与研究目标最相关的比较，并明确标注其他比较尚未完成。

### 阶段 3：效率与功能分析

汇总全部组别的：

- 任务质量；
- 路由参数量；
- 总参数量和激活参数量；
- 实际计算成本；
- 延迟与内存；
- 路由稳定性；
- Cell 功能分化。

不要仅凭某一项机制指标推断端到端性能优势。

### 阶段 4：独立复现

对于支持核心假设的结果，使用独立 Seed 和未参与模型选择的确认数据进行复现。

只有在复现后，才能将相应结论升级为确认性结果。

## 9. 判定规则

| 实验结果 | 结论 |
|---|---|
| A 优于 B 和 C，且独立确认通过 | 支持 Connection 学到了优于随机策略的路由知识 |
| A 优于 B，但不优于 C | 固定随机策略可能不足以解释结果，但尚未证明学习机制优于动态随机重连 |
| A 优于 C，但不优于 B | 结果不足以支持 Connection 学习优于所有随机基线，需要检查随机初始化和训练适应因素 |
| A、B、C 接近 | 当前实验未证明 Connection 学习具有额外价值 |
| A 优于随机控制，但未达到 MoE 的质量标准 | 路由学习机制获得支持，但模型性能仍需改进 |
| A 达到预定 MoE 非劣标准，且路由参数更少 | 支持 CLM 在目标条件下实现更高的路由参数效率 |
| A 的质量接近 MoE，但实际推理成本更高 | 不能据此宣称 CLM 已实现更好的运行效率 |
| Cell 参数差异扩大，但整体质量未改善 | 只能证明参数分化，不能证明有益的功能专门化 |

如果主要比较的置信区间过宽，无法区分有意义的改善与无改善，应报告为证据不足，而不是自动判定成功或失败。

## 10. 主要风险与处理方式

### 风险一：随机 Connection 的初始状态不公平

**处理：** A、B、C 使用相同的合法随机 Connection 作为共同起点，之后才根据组别执行不同的更新策略。

### 风险二：随机重连的扰动幅度不同

**处理：** 匹配合法拓扑约束、更新时点和连接数量，记录实际路径变化。不能匹配的差异必须报告。

### 风险三：复用历史确认集

**处理：** 新建或重新划分独立 Confirmation 集，避免用历史 Calibration 结果作为独立确认。

### 风险四：将参数分化误认为功能分工

**处理：** 同时报告功能性指标、路由与任务的对应关系，以及整体任务质量。

### 风险五：只比较参数量，不比较实际成本

**处理：** 同时报告路由参数量、激活参数量、FLOPs、延迟、内存和训练成本。

### 风险六：将单次实验成功解释为普遍优势

**处理：** 明确报告当前任务、架构、预算和 Seed 范围。只有跨独立 Seed、数据集和后续模型规模复现后，才能提出更广泛的结论。

## 12. 最终研究判据

本阶段应当分别得出三个结论，而不是只给出一个笼统的“CLM 成功”或“CLM 失败”。

**第一，路由学习价值：** 学习后的 Connection 是否在独立确认数据上优于固定随机 Connection 和随机重连。

**第二，模型性能：** CLM 是否能够在可比的任务质量、模型容量和激活计算条件下达到有竞争力的结果。

**第三，参数效率：** CLM 是否能够以更少的路由参数实现相近的模型质量，并且这种优势是否反映在实际计算成本中。

本阶段不要求 Cell 参数差异持续扩大，也不要求 CLM 立即在所有指标上优于 MoE。

最终目标是用可重复、可比较的实验结果，判断 Connection 是否学到了有价值的路由知识，以及这种知识是否能够转化为 CLM 的实际质量—计算优势。
