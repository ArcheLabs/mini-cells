# Pilot 完整文档预算规划修复

失败结果：`kaggle/clm-v04-pilot-2m-seed17-7c94a3724475-edc54d46`，发布 SHA `2b49f131bc10de4222c5af74327dcfd3fc3c7f97`。

这次 FP32 的精度、Controller 和全部六模型 GPU 一致性门禁通过。`decision.json` 的直接错误为 `cannot freeze exact target budget for benchmark`，`pilot_training_started=false`。原失败结果保留，不作为科学结论。

原规划器先贪心加入完整文档组，再从候选文档凑剩余 Targets。如果差额比最短文档还小，即使回退一个组就有解，原实现仍返回不足的计划。少量候选文档需要重复使用时也可能漏解。

修复保持已有可行计划的选择顺序。原完整文档尾部无解时允许重复使用数据流中的完整文档；仍无解则回退前缀组重新规划。绝不切断文档、添加伪 Token 或降低目标数。不可达预算明确失败。

测速 16,384、Dry Run 4,096、训练/评估权重计划 2,000,000 Targets 全部在 GPU 门禁前核验实际计数并冻结。评估使用训练权重；这里的评估计划哈希用于校验其训练身份，不代表再训练 2M。`sample-plans.json` 记录每阶段 Targets、组数、文档访问次数和计划 SHA，两个 Worker 使用相同算法复核。精度不改变样本计划。

本轮默认精度固定为前次已实测通过的 FP32，避免重跑失败的 FP16 缓存一致性路径；仍重新执行当前源码下的 FP32 门禁、双 Worker 实测吞吐和原时间预算判定。六模型各 2M、Seed17、总墙钟 7,200 秒均保持；新源码采用新实验身份，不混用旧模型/优化器 Checkpoint。

本地验证：三个针对性 CPU 回归通过（2.42 秒），覆盖原贪心尾部不可达、需重复完整文档的尾部、所有 Pilot 预算、精度切换后计划一致、原 2M 样本计数及小型断点续训/Scheduler 一致性。没有运行真实 GPU 训练，也未执行跨 Kaggle 恢复验证。
