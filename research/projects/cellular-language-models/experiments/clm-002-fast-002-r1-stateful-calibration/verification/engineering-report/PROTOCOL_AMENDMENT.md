# MiniCells：恢复数学与故事联合训练的实验连续性

**方案版本：** 1.0  
**研究范围：** CLM-002-FAST-001、CLM-002-FAST-002、CLM-001-R3f-v2  
**执行原则：** 保留历史成果、修复实验方法、先验证再训练  
**文档性质：** 待审阅的实验修订方案，不代表科学实验已获批准或已执行

---

## 1. 执行摘要

### 1.1 核心问题

MiniCells 之前已经取得两项有价值的进展：

1. 在 Story 与 Arithmetic 两类任务上，Cell 已经表现出可测量的分化。
2. 在 R3f-v2 实验中，Connection 候选曾经通过信任区域检查，并在 A-C 结构中取得后续 Cell 适应的局部质量改善。

但是，后续实验没有把这两项进展完整衔接起来。

CLM-002-FAST-001 完成了阶段 A 的 Cell 分化实验，但阶段 B 的 Connection 候选全部被拒绝，没有形成正式的 Connection 更新。

CLM-002-FAST-002 随后执行了定向校准，但存在两个需要修复的问题：

- 尺度扫描只覆盖从 1 到 1/1024，没有覆盖 R3f-v2 曾经通过的 1/4096。
- B11 联合训练条件的候选校准没有从真实阶段 B 第 50 步的模型状态生成，而是使用阶段 A 的模型状态和第 50 批数据构造候选。

因此，FAST-002 的失败不能证明数学与故事联合训练无效，也不能证明 Cell 与 Connection 无法协同训练。

### 1.2 本方案的目标

本方案采用以下顺序：

1. 保护已有实验注册、Checkpoint、数据和结果。
2. 建立独立的修订版本，不覆盖历史实验。
3. 修复真实阶段 B 状态的恢复与重放机制。
4. 恢复 R3f-v2 已验证的完整尺度扫描范围。
5. 使用独立的 Admission 数据进行候选准入检查，保持 Confirm 数据封存。
6. 先完成低预算诊断实验。
7. 只有诊断通过后，才启动正式阶段 B 联合训练。

**本方案不重新设计模型，不改变数学与故事训练目标，不放宽信任区域阈值，也不直接重跑完整的 25,000 次逻辑更新实验。**

## 3. 已确认问题与待验证假设

必须将事实和假设分开，避免在修复过程中提前决定科学结论。

### 3.1 已确认的问题

**问题 A：扫描范围不完整。**

FAST-002 没有测试 1/2048、1/4096 及更小的已注册范围，因此尚未完整检查历史上出现过可行更新的尺度区间。

**问题 B：校准状态与真实联合训练状态不一致。**

正式阶段 B 的 Connection 提案发生在对应逻辑更新的 Cell 更新之后。

对于 B11，真实第 50 步的提案应建立在此前 50 次 Cell 更新所形成的模型状态上。FAST-002 的校准过程没有执行这些主训练更新。

**问题 C：部分校准上下文重复。**

FAST-002 中，同一 Seed、同一任务条件下的 B01 与 B11 出现相同的输入哈希、损失序列和候选结果。这与两组没有采用各自真实训练轨迹的校准方式一致。

**问题 D：校准数据与确认数据的职责需要进一步明确。**

FAST-002 使用训练数据中的参考输入评估准入指标。新修订必须明确分离候选生成、准入评估和最终确认的用途。

### 3.2 尚未证明的假设

以下均为待验证假设：

1. FAST-002 失败主要由尺度扫描不足导致。
2. 在真实 B11 状态下，Connection 候选更容易通过信任区域。
3. 使用独立 Admission 数据会改变现有候选的准入结果。
4. 修复后能够恢复正式联合训练。
5. 联合训练能够改善最终模型质量。

本方案不得将任何一项待验证假设写成既定事实。

## 5. 实验阶段总览

本方案将工作分为四个阶段。

| 阶段 | 工作 | 是否允许正式训练 |
|---|---|---|
| Gate 0 | 历史证据核验、Checkpoint 与数据身份检查 | 否 |
| Gate 1 | 真实阶段 B 状态恢复、确定性重放、完整尺度校准 | 否，不运行完整阶段 B |
| Gate 2 | 独立审阅校准结果与成本，判断是否允许继续 | 否 |
| Gate 3 | 按原注册启动正式阶段 B，完成联合训练实验 | 仅在明确批准后 |

Gate 1 可以包含有限的诊断重放和候选优化，但不能将其混同为正式的阶段 B 科学结果。

如果 Gate 0 或 Gate 1 失败，必须保存证据并停止，不得自动进入 Gate 3。

## 6. Gate 0：历史状态与资产核验

### 6.1 核验历史结果

先检查：

1. FAST-001 的最终结果和每个 Seed 的阶段 A 最终 Checkpoint。
2. 阶段 B 的实际执行记录与 Connection 提案日志。
3. FAST-002 的全部 20 个校准任务及对应候选结果。
4. R3f-v2 的完整尺度扫描结果及通过记录。
5. 各实验的实际源码版本、配置身份和数据身份。

必须区分逻辑更新、优化器调用、候选提案和正式参数提交，不能混用这些计数。

### 6.2 检查真实阶段 B 第 50 步状态是否存在

对于每个需要重建的上下文，优先检查是否保存了能够精确恢复的历史状态。

一个有效的历史状态必须包含或能够验证：

- 模型参数。
- Cell 优化器状态。
- Connection 参数和相应优化器状态。
- 当前逻辑更新步数与 Token 游标。
- 数据流及其随机数状态。
- 路由探索 RNG、反事实 RNG、Python/NumPy/PyTorch RNG。
- 当前 Seed、任务条件、Arm、阶段和源码身份。
- 已执行的 Connection 提案及其状态。

只有模型权重相同，并不足以证明训练状态相同。

如果历史状态无法满足这些条件，不得将其标记为已恢复。

### 6.3 禁止反向推断训练状态

如果仅存在阶段 B Step 500 的最终 Checkpoint，不能简单地从该 Checkpoint 反向恢复到 Step 50。

必须从正确的阶段 A Step 500 父状态，按原始执行顺序确定性重放。

如果精确重放所需的状态、源码、数据或 RNG 无法恢复，则标记为 `BLOCKED`，并报告具体缺口。

## 7. Gate 1：重建真实的阶段 B 提案状态

### 7.1 需要校准的上下文

正式阶段 B 使用五个预注册 Seed、两种任务条件和四种训练 Arm。

本次诊断聚焦于 Connection 可训练的两种 Arm：

- B01：Cell 冻结，Connection 可训练。
- B11：Cell 与 Connection 均可训练。

两种任务条件：

- S：Story-only。
- H：Story + Arithmetic。

因此，需要核验的提案上下文数量为：

`5 Seeds × 2 Conditions × 2 Arms = 20`

每个上下文必须独立构造，不得复用另一个 Arm 的模型状态或候选结果。

### 7.2 正确的父状态

每个上下文都必须从对应 Seed 和任务条件的阶段 A Step 500 Checkpoint 分叉：

- B01-S 使用对应的 A-S Step 500。
- B11-S 使用对应的 A-S Step 500。
- B01-H 使用对应的 A-H Step 500。
- B11-H 使用对应的 A-H Step 500。

不能使用其他 Seed 的父状态，也不能使用未经证明的合成状态。

### 7.3 精确重放规则

如果不存在有效的第 50 步状态，执行以下重放流程：

1. 从对应的阶段 A Step 500 父状态创建独立的阶段 B 子状态。
2. 恢复原始训练配置、Cell 优化器、数据流、路由 RNG 和探索策略。
3. 执行第 1 至第 49 次逻辑更新。
4. 执行第 50 次主训练更新。
5. 在正式 Connection 候选优化开始之前暂停。
6. 保存该时点的模型、优化器、RNG、数据游标、参数哈希和成本记录。
7. 使用该状态生成 Connection 候选。

暂停点必须位于第 50 次主训练更新之后、Connection 候选搜索之前。

这样才能保留原始执行顺序。

### 7.4 B01 与 B11 的区别

**B01：**

- Cell 参数保持冻结。
- 不得产生 Cell 参数更新。
- 在第一次正式 Connection 提案之前，模型参数应符合原始注册规定的冻结行为。
- 仍需执行真实的数据流与训练前向过程，以保持提案输入及数据游标正确。

**B11：**

- Cell 按原注册进行正常更新。
- 第 50 步提案必须基于已经执行 50 次主训练更新后的 Cell 状态。
- 不得直接使用阶段 A 的原始 Cell 状态代替。
- 不得使用 B01 的损失、候选或输入哈希代替 B11。

### 7.5 重放一致性

对于相同的父状态、源码、配置、数据和 RNG，重复执行重放必须产生一致的状态身份和确定性输出。

若实际硬件或执行环境不能保证严格的位级确定性，则必须预先规定允许的数值容差，并分别记录：

- 字节级一致性。
- 参数数值差异。
- 候选方向差异。
- 关键评价指标差异。

不得在发现差异后临时扩大容差。

## 8. 数据隔离：Train、Admission 与 Confirm

### 8.1 三种数据的职责

**Train**

用于主训练和 Connection 候选生成。

候选方向可以依据 Train 计算，但不能仅依据 Train 结果宣布候选通过准入。

**Admission**

用于 Connection 候选的信任区域评估和尺度选择。

它必须在查看本轮候选结果之前完成注册、生成、哈希和冻结。

**Confirm**

用于正式实验的最终质量评价。

Confirm 不得参与候选生成、尺度选择、阈值调整、Seed 选择或失败后的重试决策。

### 8.2 Admission 数据准备

如果当前注册中不存在独立的 Admission 数据，应建立新的修订数据清单。

要求：

- 使用固定版本的生成器。
- 使用独立的生成随机流和样本 ID。
- 固定 Tokenizer。
- 记录原始文本、规范化文本、Token 窗口和文件哈希。
- 检查与 Train、Confirm 的精确重复、规范化重复、窗口重复和输入/目标窗口重复。
- 在候选尺度扫描前冻结完整数据清单。

不得将 Confirm 改名为 Admission，也不得为了避免准备新数据而重新使用确认集。

如果无法证明数据身份和隔离边界，则停止 Gate 1。

### 8.3 不改变模型目标

本次修订继续使用原来的 next-token 预测目标：

`L = 0.5 × Story NLL + 0.5 × Arithmetic NLL`

不引入：

- Answer-only loss。
- 新的任务标签路由。
- 解冻 Embedding 或 LM Head。
- 新模型容量。
- 额外的任务专用输出头。
- 为了通过校准而调整训练目标。

任务与数据角色标签仅用于数据管理和报告，不作为模型额外输入。

## 9. 完整 Connection 尺度扫描

### 9.1 扫描范围

对每个有效候选方向，执行固定的 22 个尺度检查：

- 一个零扰动基线。
- 21 个正尺度：`α = 2^-k`，其中 `k = 0, 1, ..., 20`。

即：

`1, 1/2, 1/4, ..., 1/4096, ..., 1/1048576`

必须明确包含历史锚点：

`α = 1/4096`

不能在 1/1024 处提前停止。

除非另行完成并批准新的实验修订，否则不得将扫描范围扩展到 1/2²⁰ 之外。

### 9.2 候选参数构造

对于原始 Connection 参数 \(\theta\)、完整候选参数 \(\theta^*\) 和缩放比例 \(\alpha\)，构造：

\[
\theta_\alpha = \theta + \alpha(\theta^*-\theta)
\]

只有注册中允许更新的 Connection 参数参与缩放。

所有 Cell 参数、Embedding、LM Head、Norm、Memory、Gate 及其他冻结参数必须保持不变。

每个尺度都必须记录：

- 原始候选参数哈希。
- 缩放后的 Connection 参数哈希。
- 相对于父状态的参数差异范数。
- 是否存在非零参数变化。
- 完整信任区域指标。
- 接受或拒绝的原因。

零扰动基线只用于校验评价器，不得作为成功的 Connection 更新。

### 9.3 固定准入阈值

继续使用原有阈值，不得放宽：

| 指标 | 通过条件 |
|---|---:|
| KL divergence | ≤ 0.01 |
| Action change | ≤ 0.10 |
| Path change | ≤ 0.20 |
| 参数变化 | 必须为非零更新 |

三个信任区域条件必须同时通过。

不得因为某个指标已通过，就忽略另一个指标的失败。

不得仅报告平均值掩盖单个必需检查的失败。

### 9.4 评价方法

必须复用历史实验中相同定义的指标计算方法。

固定：

- Admission 输入及其顺序。
- 路由采样规则。
- RNG 与模型执行模式。
- 路径变化的计算方式。
- Action change 的计算方式。
- KL 的参考分布。
- 模型状态与候选状态的比较范围。

如果现有实现存在多个版本，必须先确认与原始 R3f-v2 指标定义的对应关系，并在修订协议中固定具体实现。

不得在新实验中重新定义指标，使其更容易通过。

### 9.5 尺度选择规则

在所有尺度计算完成后：

1. 排除零扰动基线。
2. 排除参数没有实际变化的候选。
3. 排除任意一项信任区域指标失败的尺度。
4. 如果存在多个通过尺度，选择最大的通过尺度。
5. 如果所有正尺度均失败，则该上下文校准失败。

不得根据 Confirm 选择尺度。

不得通过多次尝试、挑选不同候选或更换 Seed 直到出现通过结果。

候选生成规则和候选优化器必须保持与注册版本一致；如需修改候选生成方法，应另立修订，而不是把它混入尺度校准。

## 10. Connection 候选生成机制

本次修订不重新设计 R3e Q 提案算法。

继续使用已注册的候选生成实现及其参数，包括：

- 12 个候选状态。
- 8 轮策略优化。
- 每个状态 6 个候选动作。
- 学习率 0.0003。
- 权重衰减 0.1。
- 梯度裁剪 1.0。

成本日志必须按实际优化器调用记录。不能将 12 个状态乘以 8 轮，直接宣称发生了 96 次优化器调用。

对于每个提案，必须记录：

- 初始策略优化器状态。
- 最终策略优化器状态。
- 实际优化器调用次数。
- 候选生成时间。
- 训练数据与 Admission 数据身份。
- 候选参数差异。
- 所有尺度的完整评价结果。

如果候选本身没有产生非零参数变化，则记录为无有效更新，不得通过缩放制造虚假的成功。

## 11. Gate 1 的继续与停止规则

本节定义的是**建议采用的新校准放行规则**，不是历史实验已经批准的科学判据。执行前必须将其写入独立修订配置并冻结。

### 11.1 建议的放行门槛

对于五个预注册 Seed，分别评价以下四类上下文：

- B01-S。
- B11-S。
- B01-H。
- B11-H。

建议要求至少四个 Seed 在四类上下文中均获得非零且通过全部信任区域检查的 Connection 候选。

即至少有四个完整配对 Seed，同时满足：

`B01-S PASS ∧ B11-S PASS ∧ B01-H PASS ∧ B11-H PASS`

所有五个 Seed 的结果都必须保留。

不得因为某个 Seed 失败而替换 Seed。

这个门槛只用于判断是否具备继续正式阶段 B 的工程与准入条件，不代表联合训练的科学假设已经得到支持。

### 11.2 如果 Gate 1 通过

必须同时满足：

- 全部 20 个上下文均完成身份核验。
- 重放与来源记录完整。
- 所有尺度扫描完整。
- 至少四个 Seed 满足上述配对准入门槛。
- Admission 与 Confirm 隔离成立。
- 成本账本完整。
- 当前修订源码的 CI 通过。
- 独立审阅确认结果没有被误读。

随后才能申请启动正式阶段 B。

### 11.3 如果 Gate 1 未通过

立即停止，不启动正式阶段 B。

报告必须明确区分：

- 候选生成失败。
- 候选方向为零。
- 尺度范围内没有通过的非零更新。
- 信任区域指标失败。
- 父状态或 RNG 无法恢复。
- Admission 数据不合格。
- 重放无法复现。
- 工程实现或成本账本不合格。

不得将失败统一写成“联合训练无效”。

如果需要进一步探索候选生成算法、阈值或更小尺度，必须创建新的实验修订，并明确说明改变了哪些变量。

## 12. Gate 3：正式阶段 B 联合训练

只有 Gate 1 通过并获得明确批准后，才允许执行正式阶段 B。

### 12.1 保留原有 2×2 因子设计

| Arm | Cell | Connection |
|---|---|---|
| B00 | 冻结 | 冻结 |
| B10 | 训练 | 冻结 |
| B01 | 冻结 | 训练 |
| B11 | 训练 | 训练 |

每个 Seed 在 Story-only 和 Story + Arithmetic 两种条件下执行完整因子设计。

每个 Seed 共八条阶段 B 路径。

### 12.2 训练预算

继续使用原注册：

- 五个 Seed。
- 每条阶段 B 路径 500 次逻辑更新。
- 每次更新 512 个有效目标 Token。
- 固定最终评价点为 Step 500。
- Connection 提案步数为 50、100、150、200、250、300、350、400、450、500。

阶段 B 最多包含：

`5 × 8 × 500 = 20,000 次逻辑更新`

主训练目标位置总量为：

`20,000 × 512 = 10,240,000`

Connection 候选搜索、失败提案、重试和其他辅助计算必须单独计入成本，不能简单地将逻辑更新数视为完整计算成本。

### 12.3 正确的父状态与参数提交

每条正式阶段 B 路径都必须从对应 Seed、对应任务条件的阶段 A Step 500 Checkpoint 分叉。

校准实验只负责确定准入机制是否可行。

不得把校准实验产生的候选参数直接写入正式阶段 B 的初始模型。

正式阶段 B 必须使用其原始注册的训练轨迹、随机状态和优化器规则。

在每个 Connection 提案点：

1. 执行当次主训练更新。
2. 根据当前真实模型状态生成 Connection 候选。
3. 使用已注册的候选治理机制执行完整尺度检查。
4. 通过所有信任区域门槛后，才提交允许的缩放更新。
5. 如果候选失败，保留原 Connection 参数。
6. 记录参数差异、优化器状态和成本。

B11 必须始终使用自己的 Cell 更新轨迹，不得共享 B01 的候选状态。

### 12.4 正式实验的失败规则

正式阶段 B 不得因为中途质量较差而：

- 替换 Seed。
- 改变训练步数。
- 放宽信任区域阈值。
- 重新选择确认集。
- 根据中途结果改变学习率或候选生成机制。
- 删除失败路径。
- 将拒绝的候选计为成功提交。

所有失败尝试都必须计入成本账本。

## 13. 最终质量评价与科学判据

### 13.1 主要评价目标

对 Story 和 Arithmetic 分别报告 Token-mean NLL。

继续使用等权重汇总：

\[
L = 0.5L_{\text{Story}} + 0.5L_{\text{Arithmetic}}
\]

对于任务条件 \(T\)，计算：

\[
I_T = L_{11,T}-L_{10,T}-L_{01,T}+L_{00,T}
\]

主要终点：

\[
I_H=L_{11,H}-L_{10,H}-L_{01,H}+L_{00,H}
\]

次要终点：

\[
\Delta I=I_H-I_S
\]

### 13.2 沿用原注册的统计规则

- 五个配对 Seed。
- 主要终点使用双侧 95% Student-t 置信区间，df=4。
- 主要支持标准：\(I_H\) 的置信区间上界不高于 -0.01。
- 次要支持标准：\(\Delta I<0\)，并满足原注册的 Holm 校正显著性要求。
- 单任务相对同 Seed、同任务 B00 基线的 NLL 退化不得超过 0.02 nats/Token。
- 所有 Seed 均须报告。
- 不允许根据最终结果替换 Seed 或延长训练。

路由塌缩、Cell 专业化、Cell 调用份额及成本指标仍须单独报告，不能用汇总 NLL 改善替代。

### 13.3 统计解释边界

FAST-001 的阶段 A 结果已用于进入阶段 B，因此必须保留原注册的选择过程和统计解释边界。

不能将通过阶段 A 门槛后使用同一组 Seed 的阶段 B 结果，宣传为完全独立的重复确认。

本轮结论只适用于本次受控数据分布、当前模型架构和既定计算预算。

即使正式阶段 B 通过，也不能据此直接宣称 MiniCells 已经具备持续学习能力、免历史重放能力或通用智能。

## 14. 成本与恢复机制

### 14.1 校准成本

完整诊断成本应包括：

- 20 个提案上下文。
- 每个上下文最多 50 次逻辑更新的重放。
- 每个上下文一次候选生成过程。
- 每个上下文 22 个尺度的检查。
- 所有 Admission 前向计算。
- RNG 恢复与重放开销。
- Checkpoint 保存和校验。
- 失败提案、拒绝候选与重复执行的实际成本。

如果所有 20 个上下文都需要完整重放，主训练重放上限为：

`20 × 50 = 1,000 次逻辑更新`

这只是校准诊断预算，不包含后续正式阶段 B 的 20,000 次逻辑更新。

实际预算必须根据设备、批次和候选评估耗时测量，不能根据逻辑更新数推断 GPU 时间。

### 14.2 成本账本

每次运行必须记录：

- 主训练更新数。
- Cell 优化器调用数。
- Connection 候选优化器调用数。
- Connection 正式提交数。
- Admission 评价次数。
- 有效 Token 数量。
- GPU 时间与峰值显存。
- Checkpoint 读写时间。
- 失败、拒绝、重试和恢复次数。

诊断报告必须明确区分训练成本与候选搜索成本。

### 14.3 中断与恢复

Checkpoint 恢复必须验证：

- Checkpoint SHA-256。
- 训练步数。
- 数据游标。
- RNG 状态。
- 优化器状态。
- 当前 Arm 与任务条件。
- 源码和配置身份。
- 已提交的成本账本记录。

如果优化器调用已经执行，但对应的 Checkpoint 和日志状态无法确定，则停止并要求人工核验。

不得在状态不确定时自动重新执行优化器调用。

回传失败只允许重试回传，不得隐式重新训练。

## 19. 最终决策标准

本方案需要回答两个不同的问题，不能将它们合并。

**问题一：Connection 准入机制能否在正确的训练状态下产生合格的非零更新？**

由 Gate 1 的真实状态重放、完整尺度扫描和独立 Admission 检查回答。

**问题二：Cell 与 Connection 的联合训练是否比单独训练产生可重复的额外收益？**

只有正式阶段 B 完整执行并满足原注册统计与质量判据后，才能回答。

如果 Gate 1 失败，结论应当是：

> 在当前注册的候选生成机制、训练状态和尺度范围内，尚未找到满足全部准入条件的非零 Connection 更新。

如果 Gate 1 通过而正式阶段 B 未通过科学判据，结论应当是：

> 在本轮受控任务、当前架构和计算预算下，尚未获得支持 Cell 与 Connection 联合训练具有额外价值的充分证据。

如果正式阶段 B 通过，则可以报告相应的实验支持，但仍须遵守数据分布、统计选择和架构范围的限制。

**最终原则：先恢复真实训练状态，再完成完整准入验证，最后检验联合训练价值。不得将前一阶段的工程失败直接解释为后一阶段的科学失败。**
