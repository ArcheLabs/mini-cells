# A3.1 · Focused L2 Norm autotuning diagnostic

The earlier broad replay protocol remains available as a historical design. The current experiment tests native configuration selection and a single controlled intervention.

MoM calls FLA L2 normalization after the routed Q/K convolution and head reshaping. The 256-wide last dimension enters the FLA `D <= 512` forward branch, which autotunes 25 combinations of row tile `BT` and `num_warps`. The Triton kernel converts loads to FP32, reduces over the feature dimension, then stores at the output precision. BT tiles rows and can change the compiled mapping. Warp or tile choices can change the implementation of the reduction. Neither a changed algorithm nor a changed numerical result follows from configuration choice alone.

Triton 3.6 initializes an in-memory cache per Autotuner. Its disk-autotune setting depends on the decorator argument or `TRITON_CACHE_AUTOTUNING`. FLA leaves that decorator argument at its default. Separate processes may therefore benchmark and select different configs, even when Triton's compiled binaries are cached. The installed `run` method chooses `self.configs[0]` when the candidate list is a singleton, bypassing prior winner selection. The intervention temporarily supplies the existing `BT=32, num_warps=4` configuration only during the two measured first-block routed normalization calls. It keeps the same FLA implementation, original FP16 tensors and original R1 error bounds.

Run P0/P2/P3 sequentially on the same GPU UUID with distinct PIDs. Every query starts from the exact historical A3 Bundle and validated query IDs. An unobserved native query checks instrumentation against the original envelope. The next measured native query records each actual `best_config`, the environment variable, and the effective cache setting. A final fresh import measures the fixed configuration. Publish exact pre-norm, post-norm and first-recurrence Q/K tensors with bitwise and layout comparisons.

Strong evidence for the hypothesis requires equal native PRE_NORM input, matching first routed slot, differing default configs, divergence both at POST_NORM and the recurrent input, and bitwise convergence across fixed runs with unchanged PRE_NORM inputs. This intervention neither opens R1-A nor changes SDK inference. A negative result retains uncertainty about the compiled kernel and execution environment.

Supply the original A3 Saved Output through Kaggle Add Input, or a fixed `A3_KAGGLE_REF` supported by the versioned Kaggle CLI, or `A3_BUNDLE_PATH`. The existing recovery and SHA-256 guard are reused. Use `kaggle_l2norm_autotune.py` on Tesla T4 with Internet and the `GITHUB_TOKEN` secret.
