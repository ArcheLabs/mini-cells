# A3.4 · Functional Impact of Numerical Execution Differences

A3.3 found differences within both process-history groups. A3.4 tests whether those execution differences change the outcome of the frozen M1-002A Bridge.

## Frozen workload

Use the original A3.3 published Bridge dataset at commit `91e8c1af3ff580f1e90e9ddb493c3d70fd8a7de2`. Validate its file SHA-256 and canonical SHA-256 before starting a GPU worker. Preserve all 12 episodes, six arms, two independent write variants, two questions per variant, candidate tokens and order. The model, tokenizer, native execution profile and dependency versions match A3.3. All model calls use the audited native L2 Norm configuration `BT=32, num_warps=4, num_ctas=1, num_stages=3`.

## Process and scoring matrix

Run P0, A1, B1, B2 and A2 on a single physical T4. Each worker runs its A3.3 history and numeric probe, then continues in the same model instance and process. The original A3.3 shared Bundle is read-only. Each Bridge worker writes its own episode Cells using R1's original grouping for identical texts; these cells are distinct from the probe Bundle and the history Write. Any cross-worker functional difference can include variability in those Bridge writes. A3.4 does not independently identify a Write or Query operator.

P0 evaluates Live A and restored Full-State E. A1, A2, B1 and B2 evaluate E. Keep original R1 teacher forcing. Each multi-token candidate gets a new cache. Single-token alternatives share a single read of the prefix distribution with no candidate tokens fed back. Each wording obtains a separate cache. The persisted Cell is checked for mutation across reads.

## Interpretation

A query succeeds only when its gold total log probability strictly exceeds every distractor. An episode succeeds only when all four queries succeed. Report query and episode gains and losses, margin and per-token gold NLL deltas, and every change in gold rank relative to any distractor, including ties. Changes among distractors are recoverable from the published candidate scores. Numeric comparisons retain the A3.3 original bounds for diagnosis and do not gate engineering completion.

Within-arm differences take precedence for the functional status. If an arm is unstable, the report calls for one targeted independent repeat of that arm. With stable arms, report any between-arm association and P0 Live versus restored differences independently. If rank and correctness never change when numerical drift is present, pause broad numerical tracing for this benchmark. A fully identical run without reproduced drift is inconclusive about the impact of prior drift.

Historical M1-002A Full Context and Cell summaries remain separate from the new A/E results. These are development results on the 12 frozen episodes. Capacity and the formal R1-B gate remain outside scope.

Use `kaggle_functional_impact.py` in the existing Kaggle Python Notebook with Tesla T4, Internet and `GITHUB_TOKEN`. One launch runs CPU preflight and the five workers, then publishes results under an independent A3.4 GitHub branch and verifies the remote SHA.
