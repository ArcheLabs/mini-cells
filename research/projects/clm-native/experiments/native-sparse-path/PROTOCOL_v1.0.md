## 0. 执行摘要：我们究竟要验证什么

CLM 的核心主张不是“MoE 可以分解成小 Cell”，也不是“二维 NCA 可以完成复杂任务”，而是：

> **在不预设固定层级或二维邻近性的条件下，少量共享参数的 Cell 能否根据自身状态，形成真正参与计算的低成本、非局部、动态稀疏路径；相对于参数、信息访问与实际计算预算相匹配的静态或集中式机制，该路径是否产生可重复的质量—成本优势？**

本次只验证上述主张的第一部分：**任意地址空间中、受限候选集内的动态连接选择、消息计算与局部状态更新**。不在本次宣称：

- 任意语义目标的无索引、次线性发现已经解决；
- 所有复杂函数都可以低成本分解为小 Cell；
- 已实现通用语言模型、在线知识增长、持续学习或 10× 整模型推理效率；
- 模型能够自主从零发现完整的功能图谱。

**短期成果**：一个具备充分负控、可复现实验、预算计量及明确否证条件的原生 CLM 原型。  
**长期对齐**：最终架构为小参数、无固定深度顺序、动态稀疏计算路径；同等能力下争取至少 10× 端到端资源效率，但**10× 不作为本次小实验的立即通关标准**。

### 0.1 必须回答的四个问题

1. **连接是否有用**：扰动学习到的具体边，而不扰动节点参数、消息数和执行预算，输出质量是否按可解释方式变化？
2. **动态性是否有用**：输入相关的连接，是否优于相同连接预算的学习静态图、随机固定图和内容无关的动态控制？
3. **路由代价是否可控**：包含候选取得、打分、地址读取、消息聚合和调度的真实总开销，是否仍优于强对照？
4. **是否可扩展**：面对位置重排、更多 Cell、未见过的计算路径，性能与费用是否呈现值得继续研究的趋势？

**四问必须分别回答**。连接扰动导致准确率下降，不足以证明“动态连接有优势”；准确率上升，不足以证明“资源消耗更低”。

## 1. 为什么现在修改实验路线

### 1.1 结合此前 MiniCells / CLM 的实验经验

此前对话及研究总结中出现以下记录，供定位历史产物使用；**这些不是本文件重新独立审计后的仓库实测结论，M0 必须查验源码、原始日志、commit 和完整评估协议**：

| 历史实验 | 之前记录的主要现象 | 对当前实验的约束 |
|---|---|---|
| Experiment 003/004：Graph Cell | 图调度在部分设置下开销较大 | 禁止用逐 Cell Python 调度作为性能实现，并在成本账本中显式计入调度 |
| Experiment 007：TextNCA 30M | TinyStories 约 100M token 下，PPL 曾报告 5.3532 vs 5.3290；吞吐约慢 2.25× | 不重复“递归局部网络也能训练”的演示；一定比较质量和实际延迟 |
| Experiment 015 / 015c：动态稀疏拓扑 | 曾报告形成结构但连接因果价值不充分、结果弱于较强对照 | 必须做**等成本的连接干预**与路径日志分析 |
| Experiment 016：Cell 生长 | 曾报告局部结构改变可观察，但能力保持与时间成本不理想 | 暂不实现生长、分裂、生命周期系统 |

建议 Codex 首先审计已有 `research/experiments/004-cell-graph`、`research/experiments/03-routing-and-growth`、`research/validations/`、`research/artifacts/`、`research/minicells/` 等路径；路径仅作为此前盘点的线索，以实际仓库为准。历史数字若无法从原始结果确认，应标记 `UNVERIFIED`，不得写入本次论文式结论。

### 1.2 为什么不以二维网格作为主实验

固定二维邻域隐含空间相近对应计算相近的强先验，且远端消息至少需要多个同步步骤。对于抽象计算，这个先验不一定成立。我们已经有相关局部/递归实验经验，再次把标准二维 NCA 作为主线，新增信息有限。图消息传递中的远距离信息瓶颈在既有研究中也已有明确讨论。

**保留局部计算，取消物理局部连接约束。**

### 1.3 为什么也不采用全量任意连接

允许任意 Cell 之间存在边，**不等于每一步计算所有 Cell 对的相关性**。若先扫描 `N×N` 打分，再只保留 Top-k，仍属于昂贵的全局连接发现。实际计算复杂度和内存访问都必须诚实计量。

本项目采用**任意地址 + 候选受限 + 稀疏活跃**机制，直接测试其优势及限制。

## 2. 研究假设与否证标准

### H0（工程前提）：独立的 Cell 状态和真正的边依赖

模型拥有多个可分别更新的状态槽，图边改变会改变读取对象，并可能影响后续状态及任务输出。必须能检查消息实际从源 Cell 到达目标 Cell，且不能通过旁路全局聚合、偷看目标标签来绕过连接。

**H0 非科研突破**；只是防止实现错误及伪动态路径。

### H1：动态边的独立计算价值（核心）

同样的 Cell 更新函数、存储状态容量、训练数据和**实际端到端预算**下，按运行时状态选择的非局部稀疏边，相比（a）随机固定稀疏图、（b）学习后固定的稀疏图、（c）相同容量的无边更新/集中式控制，能够获得更优的任务准确率—成本帕累托点。

**预注册反证**：在公平且训练收敛可比的条件下，动态模型未能优于最强可比对照，尤其是具备同样地址访问权限的轻量可学习控制器，或优势完全消失于路由与消息成本；结论为“在该任务分布和预算下未获支持”，而非一般理论否定。**只在天然要求动态寻址的题目上击败固定图，不构成有说服力的核心创新。**

### H2：连接的因果作用

保留所有训练后参数、Cell 状态和激活节点数量，只替换边的目标，同时保持每节点度数、消息次数、连接生成所见信息和预算，模型质量显著下降；恢复原边后质量恢复。还须配合错误路径定位、边可达性分析，确认结果不是简单分布偏移。

**注意**：H2 通过只是“边确实被使用”，不等于 H1 通过或学出了通用知识结构。

### H3：计算路径的结构泛化（次核心）

训练只见较短路径和较小规模；测试通过未见过的路径组合、节点编号重排和更大 Cell 数量，动态模型在预算匹配情况下表现不差于强基线，最好取得显著优势。

### H4：实际效率的可扩展前景（工程门槛）

比较真实耗时、有效运算量、峰值内存与地址访问；若动态图只能在执行前执行全局搜索、或小计算被设备调度吞没，则不能声称得到资源效率优势，即使准确率更高。

## 3. 数学定义与可实现的计算模型

### 3.1 Cell 状态和共享参数

令有 `N` 个 Cell，状态为：

\[
S^{(t)} = (s_1^{(t)},\ldots,s_N^{(t)}),\qquad s_i^{(t)}\in\mathbb R^d.
\]

初始状态由一个**所有对照一致**的编码器产生：

\[
s_i^{(0)} = E_\psi(x_i,\mathrm{role}_i).
\]

`role` 只包含任务允许的身份/类型信息，不能编码答案或正确路径。采用共享的 `E`、消息算子 `V_θ`、更新函数 `F_θ`；可以有少量状态相关的执行门控，不为每个 Cell 配置独立大型 FFN。Cell 状态不要求固定的知识语义，也不预先分配“记忆 Cell / 推理 Cell”。

### 3.2 有界候选发现：绝不偷偷做全量 Attention

对于当前活跃源 Cell `i`，一个**同样计费、信息可见范围严格受控**的候选生成器产生：

\[
\mathcal C_i^{(t)} = \operatorname{Candidate}(i,S^{(t)},X,\mathcal I_t),\quad |\mathcal C_i^{(t)}|\le c.
\]

- `c` 是候选上限，不是已激活边数。
- `I_t` 为地址或索引结构，生成和维护成本进入账本。
- 从候选中最多选择 `k` 个邻居，`k ≤ c`，**目标编号可分布在任何 Cell 位置**，不受二维邻域限制。
- 禁止在推理路径中计算所有 N 个 Cell 的 Key，再做 Top-k 并谎称 `O(k)` 路由。
- 禁止读取未候选 Cell 的私有状态用于候选评分。

**研究边界**：v1.0 首先评估 *given bounded candidates*（受限候选发现）下的动态选择，而不是声称能在任意内容寻址任务中零代价发现相关 Cell。涉及索引构建或刷新时单独计费，不能由训练阶段免费“预知”测试时地址。

### 3.3 稀疏连接决策

针对 `j ∈ C_i^t` 计算：

\[
a_{ij}^{(t)} = r_\phi(s_i^{(t)},s_j^{(t)},q_i^{(t)},e_{ij}),
\quad
\mathcal N_i^{(t)}=\operatorname{TopK}_{j\in\mathcal C_i^{(t)}}(a_{ij}^{(t)},k).
\]

其中 `q_i` 为当前局部任务/上下文状态，`e_ij` 仅为允许的边元信息；不要为每对 Cell 创建可训练表。训练可对 `c` 个候选使用软权重，推理必须以硬 `k` 条边真实执行，评估时不运行软全候选图。

### 3.4 有信息流的消息与状态更新

\[
m_j^{(t)}=\operatorname{Aggregate}_{i: j\in\mathcal N_i^{(t)}}
\left(\alpha_{ij}^{(t)} V_\theta(s_i^{(t)})\right),
\]

\[
s_j^{(t+1)}=s_j^{(t)}+u_j^{(t)}F_\theta(s_j^{(t)},m_j^{(t)},x_j),
\]

其中 `u_j^t ∈ {0,1}` 表示本轮是否真正更新。所有未更新 Cell 保留状态。采用显式同步轮次（先从 `S^t` 读、后写 `S^{t+1}`），消除偶然的 Python 执行顺序影响。

第一版固定 `T` 上限，并允许提前终止。活跃集合可由前沿消息、局部门控产生；候选、边、消息、更新和终止判断都有真实成本。

### 3.5 对“高维表示”的严格理解

全局联合状态维度为 `N·d`，单 Cell 小并不意味着联合状态必然低维；但 `N·d` 也不代表免费获得该维度的有效函数能力。任意瓶颈、消息带宽、拓扑路径及状态读写都会形成约束。雅可比矩阵可以用于定位状态更新是否退化，但**满秩不是高表达能力的证明**，不把全雅可比分析当成本次前置门槛。

### 3.6 开销模型：稀疏执行不是零开销

令第 `t` 轮活跃源数 `A_t`，候选 `c`、出边 `k`、状态维 `d`，一次运行至少包含：

\[
C_{total} = C_{encode}+ \sum_t (C_{candidate}+C_{score}+C_{gather}+C_{message}+C_{update}+C_{schedule}) + C_{readout}.
\]

若每次候选发现只枚举至多 `c` 个、并且可直接访问对应索引，则候选相关评分约与 `Σ_t A_t c` 成正比；具体 FLOPs 再乘以使用的投影维度。若内容检索必须扫描所有 `N` 个 Cell，则变为 `Σ_t A_t N` 量级，必须如实报告。稀疏图还可能受随机访问、kernel 发射、同步和硬件占用率限制。

**不得把路由网络视为免费**；不得将密集矩阵 mask 之后的零元素误认为没有执行。

## 4. 第一个不可妥协的决策：问题输入如何支持非局部连接

如果任意连接需要先知道目标地址，我们必须说清楚地址来自哪里。否则实验很容易偷渡一个“拥有全局知识的 Router”。本次将这个问题显式分为两种情形：

1. **显式地址候选（本次主要研究条件）**：任务输入给每个 Cell 一个不泄漏正确选择结果的候选地址集合（至多 `c` 个），模型根据当前状态选择，并完成动态多步计算。这允许检查动态边与状态演化的价值，但不证明“任意目标可自主发现”。所有基线获得**相同候选列表**。
2. **无地址的内容关联（本次不训练，仅列为长期开放问题）**：模型需要从大量 Cell 中发现相关候选。必须提出实际索引、层级目录或其他检索机制，并计入维护与查询成本，不能直接假设次线性。

**因此，v1.0 的准确科研主张是：有限候选下，状态依赖的非局部稀疏计算路径是否具备独立价值。** 这并非对 CLM 完整终极假设的偷换，而是把最困难的两个未知——*发现候选*和*在候选中学习有效计算*——分开验证。

## 5. 研究任务：两个互补任务 + 一个必要负控

不要只做迷宫、Sudoku 或容易偏袒局部图的二维任务。不要依赖预训练 LLM，也不要重复训练大模型。每个问题实例都由确定性生成器产生，答案由外部精确求解器验证。

### Task A：输入依赖的非局部多跳变换（主任务）

- 每个实例是 `N` 个打乱顺序的状态槽；槽携带局部变换、候选目标地址和可见条件位。
- 一个起始槽持有计算值/任务上下文；每步根据**当前累积状态 + 当前槽信息**选择一个候选目标并应用槽上的小型变换。
- 正确目标随实例、步骤和中间状态变化；不存在统一的固定拓扑或固定层级顺序。
- 训练不提供正确执行路径标签，仅提供结果及可选的中间状态自监督（默认不提供 oracle 路由监督）。
- 所有模型获得同样的候选地址，候选顺序打乱；标签不能通过首候选、索引大小、节点排列等捷径推断。
- 为避免纯离散模运算给神经网络制造无关的难度，第一版优先采用稳定、可标准化的有限维连续仿射/门控变换；精确答案由独立参考执行器生成。路径选择条件需避免训练集中的固定位置捷径。

**必须配对一个明确的符号执行器基线**：若输入已经包含足够的确定性规则，手写直接指针执行器可能又快又准。CLM 即使学会该任务，也不能据此声称比算法更高效；此任务主要验证**能否学会动态路径及其成本**，而非证明 CLM 的普遍算法优势。**更不能仅凭在 Task A 上优于固定图就宣称创新成立**：任务定义本来就要求输入依赖的边，真正关键是相对同样能够根据输入选择地址的可学习控制器所产生的附加收益。

### Task B：状态变化驱动的条件通信（主任务二）

- 一批 Cell 同时收到有限的局部状态，后续节点选择依赖上一步消息产生的状态，而不是只依赖输入静态元信息。
- 目标需汇总多个条件分支的结果；不同输入形成不同的、有分叉/合并的通信图。
- 节点重新编号、初始状态轻微扰动和消息到达顺序变化不得改变精确答案（若任务定义无序）；用此检验是否真正学习状态计算，而非记忆位置。
- 相同最大分支度和候选规模下，比较动态图、学习静态图和轻量中心控制器。

**必要排除条件**：若测试数据可以由输入的某个全局平均池化或直接读出轻松完成，立即修复数据生成器；必须通过强的无边捷径基线诊断，而不是不断增加模型大小。**Task B 是本次判断 CLM 架构独立价值的主任务**：即使所有模型都有相同的输入依赖地址访问能力，也应检验 Cell 间状态计算是否有增益。

### Task C：静态连接/局部无关的负控任务

- 用相同输入尺寸和目标复杂度生成不需要随状态改边即可求解的问题。
- 期望动态 CLM 不应在该任务上“天然”领先所有对照；它的路由开销反而可能成为负担。
- 用于揭露“我们只选择了最适合动态图的任务”的评估偏差。

### 5.1 数据协议

- 使用 `train / dev / sealed_test` 三套固定 seed 范围；不同 split 的底层实例种子、路径模板和组合方案均隔离。
- 训练内分布与跨分布分别报告，不混为一个数字。
- OOD 一：更长路径深度（非简单增加节点）；OOD 二：节点编号置换；OOD 三：N 更大但候选度与规则类型不变。
- 独立生成器和参考求解器交叉自检，随机实例做手工 spot check。
- 若提供边候选集，其生成过程不得使用最终答案或正确路径作为显式泄漏来源；若根据图实例构建候选集合，需保证候选包含正确目标的覆盖率一致且**记录这个条件化任务定义**。

## 6. 核心对照：少而强，而不是实验矩阵无限扩张

| ID | 模型 | 边/路由 | 目的 | 必要性 |
|---|---|---|---|---|
| B0 | 共享参数循环网络 / 小型状态机（信息匹配） | 无 Cell 间稀疏图，允许容量匹配的控制器 | 排除“只是循环更深或参数更多” | 必须 |
| B1 | 固定候选选择策略的稀疏 Cell 图 | 输入无关的固定排序/哈希优先级，在每实例的同一候选列表中取 k 条边 | 最小稀疏消息基线，**不拿它单独证明动态性创新** | 必须 |
| B2 | 学习的静态候选偏好图 | 学习源身份/候选地址或槽位的固定偏好，测试时不读取运行时变化的 Cell 状态，仍只从同一候选列表取 k 条 | 检验是否需要状态依赖，而非仅用已训练静态连接规则 | 必须 |
| C0 | **原生 CLM 动态稀疏图** | Cell 局部状态驱动、候选受限、硬 k 条边 | 主模型 | 必须 |
| B3 | 候选范围相同的轻量**可学习集中式/逐步控制器** | 同样候选、同等状态读权限、无全量 N² 读取，允许根据当前状态条件选择下一跳 | 排除只是 Router 位置改变；**核心强基线** | 在 C0 优于 B1/B2 后，正面结论前必须 |
| ALG | 显式算法/直接地址执行器（Task A） | 确定性规则 | 防止把已知算法伪装成学习突破 | 必须 |

B0、B1、B2、C0、B3 必须匹配：初始输入信息、参数量（建议尽量在 ±5% 内）、state 总容量、候选可见信息、最大消息数、最大轮次和**实际成本区间**。无法精确匹配时报告差异，并比较质量—成本帕累托曲线，不得只选单点。

**比较公平性的重要例外**：如果每个实例的候选地址列表不同，那么“所有输入都使用完全相同的绝对边集合”不可能同时满足受限候选协议。故 B1/B2 指的是**固定/学习但不依赖当前运行时状态的候选选择策略**，不是错误地要求绝对节点地址永远不变。另应在固定候选图的子集任务中报告真正的绝对静态图控制。B2 必须具有真正可优化的偏好，而不能把随机图固定后称为“学习静态图”。B3 不能利用更大的信息访问预算，但必须足够强，可用共享循环控制器、同候选逐步查询与消息更新。**只击败 B1/B2 不足以得出 H1 正面结论。**

**二维 NCA**：不重新作为主要训练版本；可以引用历史结果和文献作为背景，若主结果无法解释再运行一个单次小控制，而非默认加到矩阵中。

## 7. 真正的因果评估：不能只看形成了什么图

### 7.1 必须保留的干预

- **边目标重排**：保持每个源 Cell 出度、活跃源数量、消息总数，选择候选范围内的替代目的地；提供随机种子与重排方法。
- **静态冻结**：在测试集上强制每个 Cell 使用训练期最常见的边，比较与运行时动态边差异。
- **同预算随机动态边**：每步在相同候选中随机取 k 条边，排除“只要会变就更好”。
- **消息零化/重分配**：区分收益是具体地址、消息内容，还是额外的非线性计算。
- **节点重编号**：输入与目标同步置换，检查置换等变/不变性（有明确角色的特殊节点除外）。

### 7.2 如何避免对连接因果性得出错误结论

**打乱图后掉分只是必要信号，不是充分证据。** 必须同时满足：

1. 重排的节点和消息数量相匹配；
2. 训练时曾见过不同合法连接，避免只测 OOD 断边；
3. 对相同测试实例进行 paired evaluation；
4. 恢复原边后表现恢复；
5. 在与 B1/B2/B3 的整体对比中仍存在有用价值；
6. 路由并非从答案或全局 oracle 偷读信息。

**关键观察量**：每步路由熵、候选覆盖率、出入度分布、唯一触达节点数、路径长度、重复访问率、消息范数、选择结果随状态变化的相关性、边替换引起的输出变化、真实成本。

## 8. 训练计划：从可微候选选择过渡到真实稀疏执行

### 8.1 起始实现

- PyTorch；共享 Cell 更新网络、小型消息投影、小型候选打分网络。
- 先同步更新、固定最大步数，默认没有动态 Cell 生长/分裂。
- 训练阶段可对 c 个候选用 Softmax/Gumbel-Softmax 或 Straight-Through 技术作为**可微近似**；结果需要和硬离散推理的行为单独报告。
- 设置路由探索以避免过早坍缩；监测不同 Cell 的梯度覆盖、被访问次数及梯度范数。
- 训练后以真实离散 Top-k + 少量状态更新运行，不允许用训练时软全候选执行的速度冒充最终速度。

### 8.2 损失函数（主项与明确约束）

\[
\mathcal L = \mathcal L_{task}
+\lambda_{ops}\widehat C_{ops}
+\lambda_{io}\widehat C_{io}
+\lambda_{route}\widehat C_{route}
+\lambda_{stab}\mathcal L_{stab}.
\]

- `L_task`：任务正确性；优先保证与参考求解器目标一致。
- `C_ops`：Cell 更新与消息计算的代理成本；**真实成本另实测**。
- `C_io`：读写节点状态、候选列表与边索引。
- `C_route`：候选评分、选择和调度。
- `L_stab`：可选状态范数/迭代数值稳定项，避免隐藏状态爆炸；禁止把额外目标当作“知识模块化”证据。

不要一次扫描十几种损失权重。固定一组简单预算/硬上限，若不可训练仅允许预注册的一次有限调整。所有对照采用相同调参预算。

### 8.3 控制训练不稳定性

- 路由和 Cell 参数可以联合训练，但必须记录二者梯度覆盖及失衡；若出现训练坍缩，可采用少量 warm-up 使候选边被充分探索。
- 不能在没有对应强对照时把固定轮训练的成功归因于内生路由。
- 检查软硬路径差异、死 Cell、消息无效、某个 hub 节点汇聚全部信息、循环不停止等退化模式。
- 固定最大轮次与消息预算，超限时硬停止并报告失败率，不自动增加计算直到答对。

## 10. 统计与成功定义（必须预注册）

### 10.1 一次筛选不等于“已证明”

- 筛选阶段使用固定 1 个 seed，结果标 `SCREENING`。
- 可能为正面结果时，核心模型至少运行 3 个独立 seed，报告均值、方差/区间和 paired per-example 差异。
- 如果算力不足以重复，不得宣称显著优势；只能给出探索性迹象。
- 使用 sealed test，只在规则与代码冻结后评测。参数调节基于 dev。

### 10.2 门槛：优先帕累托而不是任意 10% 数字

**主要科学结论 `PASS_H1`** 需要同时：

1. **Task B（主判别任务）**：C0 在**匹配实际端到端推理预算**下优于最强的具备动态状态寻址能力的 B0/B3，差异跨 seed 稳定；
2. Task A 通过机制正确性、地址寻址与成本检查；Task C 没有出现无法接受的负控异常，并如实报告；
3. H2 的边干预说明连接的具体目标具有非装饰性的计算作用；
4. 训练/测试时不依赖全图扫描或 oracle 目标地址；
5. OOD/置换结果没有揭示模型只记忆 Cell 编号或路径模板；
6. 真正的消息与路由开销被测量并计入成本。

如果 C0 准确率更高但成本也更高，标 `QUALITY_GAIN_ONLY`，不标 `EFFICIENCY_PASS`。如果仅能在预设动态最有利的 Task A 中领先，且 B3/ALG 已解决得更好，则定性为 `TASK_SPECIFIC_SIGNAL`。

**建议报告曲线而不是单点**：固定准确率阈值下总成本；固定总成本下任务错误率；规模 N 与推理步数增长曲线。预注册阈值可在 M0 根据最简单基线的可达质量固定，不能根据 sealed test 事后更改。

### 10.3 允许的结论标签

- `NOT_RUN`：硬件或预算不支持；
- `IMPLEMENTATION_FAIL`：运行机制或对照有缺陷；
- `INCONCLUSIVE`：数据/重复实验不足；
- `NO_SUPPORT`：完整有效对照下未观察到动态边独立价值；
- `QUALITY_GAIN_ONLY`：多计算获得更高质量；
- `TASK_SPECIFIC_SIGNAL`：只在特定构造任务有效；
- `SUPPORTED_IN_DISTRIBUTION`：同预算、已见分布内有稳定增益；
- `SUPPORTED_OOD`：并有未见组合/规模的可靠改进；
- `EFFICIENCY_PASS`：质量匹配前提下，实测成本优势可靠。

**失败不能直接宣称“CLM 理论被否定”；成功也不能直接宣称已实现 10× 大模型。**

### M2：主比较（一次完整、成本匹配的筛选）

**动作**：按统一预算训练 B0/B1/B2/C0；完成 Task A/B/C 的 dev 评估和成本画像；不要调成只对 C0 有利的任务。

**交付**：训练曲线、质量—成本图、原始结果、初始失败分析。

**提前停机**：C0 与强基线差距巨大且出现明确结构性原因（例如候选泄漏、通信成本超限、系统性梯度坍缩）时，允许一次有限实现修正后重测；仍不改善则 `NO_SUPPORT/INCONCLUSIVE`，不无限次搜索。

### M3：因果干预 + 必需的中心路由强对照

**进入条件**：M2 中尤其 Task B 上的 C0 存在可信的正面趋势；仅 Task A 击败固定图不构成进入条件。

**动作**：B3；边替换/冻结/随机动态；节点置换；route-cost 分解；Task A 的直接执行器基线；必要的 3-seed 复测。

**交付**：`CAUSALITY.md`、`BASELINE_FAIRNESS.md`、错误实例及路径可视化（以诊断日志或图片形式；不是 UI 开发项目）。

**停机**：收益完全由更高的路由 FLOPs、更多外部信息、更多模型参数或更弱基线导致，不再写正面 CLM 论断。

### M4：结构扩展评估与最终报告

**进入条件**：M3 具有至少一种可信的因果计算收益。

**动作**：冻结参数，测试 N、步数和重排 OOD；记录误差、推理延迟、状态内存、调度成本相对规模变化。**不重新训练更大模型**。

**交付**：`REPORT.md`、复现实验脚本、结构性结论与下一轮建议：支持继续 / 仅工程机制有效 / 暂停并回到学习规则研究。

### 12.1 核心接口

```python
class CandidateProvider:
    def candidates(self, active_ids, state, instance) -> CandidateBatch:
        """Bounded candidates; log index lookup/read cost. No oracle labels."""

class SparseRouter:
    def route(self, active_ids, candidates, state, hard: bool) -> EdgeBatch:
        """Return <= k outgoing edges per active node, plus trace/cost."""

class CellDynamics:
    def step(self, state, edges, messages, active_mask) -> State:
        """Synchronous state update: only true active nodes are recomputed."""

class ExperimentRunner:
    def evaluate(self, model, dataset, budget, interventions=None) -> Metrics:
        """Same data, information availability, and cost definition for all."""
```

**避免**：每个 Cell 一个进程；每个连接一个独立大矩阵；每次路由构造 `N×N` 全量得分矩阵；硬路由推理时仍计算全部 Cell；从答案或求解器标签取得正确下一跳；只以估算 FLOPs 替代真实延迟。

## 13. 已知理论边界与本项目不应做出的结论

1. 任意连接可表达更短路径，但**连接发现未必便宜**；在未知语义目标中，若没有可利用索引，无法先验宣称常数时间寻址。
2. 小参数共享 + 反复计算不保证相同资源下优于稠密矩阵网络；长路径、随机访问和 GPU 低利用率可能更贵。
3. `rank(J) = full` 不代表函数复杂性或泛化能力，且局部消息瓶颈会约束实际信息传输。
4. 图拓扑“看起来合理”、连接扰动会降分，都不足以证明它比强基线更有效。
5. 算法合成任务是机制验证工具，不是自然语言模型的代理评价；任务可能先验有利于动态图。
6. 学到图路径不等于学到独立知识单元；本次不预设 Cell 必须具有可解释的语义角色。
7. 动态候选选择可以有专门的中心控制器；**内生路由的价值必须通过信息和成本匹配实验证明，不能靠定义获得**。
8. 若只在给定候选地址时有效，结论必须限定为 `bounded-candidate learned sparse routing`，不能宣称完成了自由内容寻址。
9. 本次实验不能证明最终在通用 LLM 上实现 10×，但可以决定动态连接是否值得继续作为 CLM 基本计算机制。

## 16. 项目负责人最终决策标准

**继续 CLM Native**：动态连接的具体目标存在可验证的因果作用；在 Task B 上相对于同样能状态驱动寻址、且成本匹配的轻量集中式控制，出现稳定的质量—成本优势或可信 OOD 泛化信号；没有隐藏全局搜索成本。单独击败固定图不合格。

**优先改路由学习机制**：边参与计算，但训练不稳定、死 Cell、软硬路由落差大，或精度对预算极端敏感。

**优先改候选发现机制**：在给定候选的主实验有效，但真实语义内容寻址仍需全量扫描；不得直接迁移到大规模 CLM。

**暂缓动态图主张**：连接学到了可见结构但不胜过强基线；或省去的节点计算被路由/内存访问完全抵消。可以保留基准实现和负面结论，不因过去投入继续追加训练。

**不需要立即确定最终 Cell 数量、状态宽度或完全任意图的长期形式。** 下一轮架构应当由本次真正得到的因果与成本证据决定。
